# Release decisions

Judgment calls made when building this repository. The audit's own log, 64 entries, is [audit/DECISIONS.md](audit/DECISIONS.md).

1. **Structure.** The suggested layout is kept, with two additions. `audit/` holds the audit as it ran, because its scripts depend on their relative paths. `originals/` holds a filtered snapshot of the audited code, because a rerun must not depend on the author's folders.
2. **History policy: fresh.** The audit's git history has personal paths in many files, so it cannot be published as is, and scrubbing it would make its hashes meaningless. The repository starts from one commit, and the audit's commit log is summarised in [audit/CHANGES.md](audit/CHANGES.md).
3. **Effect of a fresh history.** Preregistration commits for the audit are private. Their hashes are listed for reference, and an outside reader cannot check them. The forward freeze is anchored on the SHA-256 of its content and the first public push, not on the commit hash.
4. **Paths.** Committed code holds tokens such as `@GANN_ROOT@` where the originals held folder paths. `audit/tools/render_paths.py` fills them inside a clean clone. No absolute path is committed, and `scripts/verify.py` fails if one appears. Originals otherwise keep their code. Saved outputs that contained paths carry the same tokens or a repository path.
5. **Originals are filtered, not rewritten.** Allowed: code, specs and small result files. Removed: market data, logs, account state, live bot files, and credentials. In `config.py` the login fields are blanked and strategy parameters stay. Wording that named a broker, a login or a private folder is replaced with a neutral term. No rule or parameter changed.
6. **Excluded work.** 18 entries derived from third-party signals stay in the ledger as counts, each with a one-line reason and a neutral ID, because removing them would flatter the rest. Their code and results are not published. Three public-channel entries are anonymised as CHANNEL-A, CHANNEL-B-SCORE and CHANNEL-C. CHANNEL-B-SCORE stays UNVERIFIED and out of every summary.
7. **Removed from `originals/`.** TA-LAB rounds 3, 7 and 10 are analyst-derived and never ran in the audit. `d_revival/ict_mix.py` imports private bot code, so its stage cannot be rerun here. Its stored log stays. The logs of the two public-channel reruns are removed because they name channels.
8. **Reproduction levels.** Broker MT5 exports cannot be downloaded and may not be redistributed, so "a download script for every dataset" cannot be met. `scripts/download_data.py` covers every dataset it can, and states the rest. Public, broker and dated groups are marked in [data/manifest.csv](data/manifest.csv). The `public` level skips stages that need broker bars, and [REPRODUCE.md](REPRODUCE.md) lists them.
9. **Yahoo intraday.** The SPY and QQQ intraday bars behind TVS-1 are no longer served for those dates, so they cannot be fetched again. They are marked `dated`.
10. **Forward job.** The monthly update runs as a scheduled GitHub Actions workflow. The frozen code calls `api.binance.com`, which can refuse cloud addresses, and it cannot be edited. The workflow puts a small `curl` wrapper first on `PATH` that sends the same request to `data-api.binance.vision`, Binance's public market-data host, which returned identical klines when tested. The frozen file's hash is unchanged.
11. **Failed-download file.** `calendar/dxy.csv` turned out to be a saved web error page, not data. `blueprint_filters.py` reads `dollar.csv`, so nothing uses it. It is left out.
12. **Patch scripts.** The one-time `patch_*.py` scripts that edited audit reports are not published. What they changed is in [audit/REVIEW_F.md](audit/REVIEW_F.md) and [audit/CHANGES.md](audit/CHANGES.md).
13. **Spec files.** Where a preregistration exists it is copied to the experiment's `spec.md` as found, apart from the path and wording scrub in item 5.
14. **LBO event calendar.** `originals/london-breakout/data/calendar/high_impact_events.csv` is committed although other data is not. It is 471 public release dates, each row naming its source, and holds no prices.
15. **Dated N bug in this build, found and fixed.** The first full run from a clean clone gave different dated-N figures, for example XM-1-A1 at 0.613 and N 1,789 against the stored 0.705 and N 569. The cause was mine: the release build had shortened the dates of excluded ledger rows to the month, and `"2026-10" <= "2026-10-13"` is true as a string, so later rows were counted as earlier. Stored values were right and were not changed. Excluded rows now keep their full dates.
16. **Ledger family labels.** `registry/trial_ledger.csv` keeps the label `analyst/copy` on all 21 rows it held in the audit, 18 excluded and 3 public-channel entries, so `audit/stats/TRIAL_COUNT.md` and `family_counts.json` regenerate byte for byte. `registry/experiments.csv` shows the same rows as `excluded` and `public channels`.
17. **Other inputs added after that run.** `bls_2015.htm` is committed: a BLS release schedule, the only year's page the code parses. A survey script in the page held the visitor's IP address, and the public copy has it set to 0.0.0.0. The parser reads table rows only, so its output is unaffected. The pages saved for 2016 to 2026 are a not-found page and Wayback wrappers with no schedule. Nothing reads them, those years' dates are written in `build_calendar.py`, and they are left out. `tvsearch/results/all_runs.csv.gz` is committed, 64,521 rows of stored search results. `research/trades.db` is not committed, because it holds demo balances, so it is listed in the manifest and E6 cannot be rerun by a reader.
18. **Hash checker.** `render_paths.py` used to fill the tokens inside `check_hashes.py`, which disabled its path normalising and made `data_profile.json` look different. It now skips that file.
19. **Tick data gaps, found during the release and not fixed.** A test fetch for `REPRODUCE.md` led to a check of hours with ticks in every tick file. Two months the audit used are incomplete. `xauusd-bi5-2018-09.csv` lacks 174 trading hours, including 21 to 28 September, so the FOMC decision of 26 September 2018 has no ticks. E4-NEWS skips an event without ticks, so that meeting is missing from its 2018 FOMC pool, and HPF, through `powell_lab.py`, reads the same file. `xagusd-bi5-2016-04.csv` lacks 386 of about 501 trading hours, which H3-SILVER's silver bars are built from. The cause is the downloader, which writes an empty hour when a request fails or is throttled. `xauusd-bi5-2026-06.csv` is short by design, because the pull stops on 19 June 2026. The stored results stand as computed, and the effect of these gaps on E4-NEWS, HPF and H3-SILVER was not measured. Measuring it would be a new run with its own preregistration.
20. **Changes from the release's cold review, 2026-11-03.** A fresh Claude agent that had not seen the work reviewed the built tree. What it found and what changed:
    - **Sealed H-20 prediction withheld.** `research/goldbot/prereg/H20_PREDICTION_SEALED.md` was in earlier local builds, none of them published, although the audit says it stays unopened. It is left out. Its SHA-256 is `6d6ec3edb7ba812e0b5dd0d63a7b9501bcbfc3e4d0810a43586d08ed5a94e4e4`, so a later release can show it is unchanged.
    - **Names removed from copied files.** The excluded analyst's names, the name and result of an excluded study, and a broker's initials were replaced in the copies of `research/tune1/PREREG.md`, `price_action/recent.py`, its log, a code comment in `d_revival/sim.py` and the HLCOPY-1 registry note. Two machine details were replaced in `tvsearch/README.md`. The edits are listed in `tools/build_wording.py` (private build tool), and their effect is visible in the files. The public copy of `tune1/PREREG.md` therefore no longer matches the hash in its registry row, `b63b3eac`.
    - **Audit log made readable.** `audit/DECISIONS.md` was written to the author during the audit. In the public copy, second-person wording now names the author, details of the author's machines are replaced, and a note at the top says so. No decision was changed. `audit/REVIEW_F.md` now says its reviewer was a separate Claude agent.
    - **Labels and counts.** Small samples labelled, the TVS-1 DSR explained and the TRIAL_COUNT exception stated, all in the audit repository (`audit/CHANGES.md`, last section). The audit report's 74 is marked as the audit's own run. The clock-bug wording now says most results fall and some rise. FINAL_v3's 1.040 is called the measured cost matrix. The 179,000 is called a floor, with the TVS-1 redraw beside it. The traceability check is described as what it is: a number appears in the evidence, not that it describes the right thing.
    - **Copied specs marked.** Every `spec.md` copied from the originals starts with a note that its claims are the original work's and may be superseded.
    - **Reproduction.** `make_audit.sh` now makes a relative `DATA_DIR` absolute before it changes folder. The forward workflow now refuses a manual run that is not a dry run before 2026-12-01.
    - **Not changed.** The forward test stays labelled RUNNING, as the author decided (audit DECISIONS 15), now with "no forward trades scored yet". The preregistrations in `audit/prereg/` and the copied specs keep their wording, including "the user". iFVG: see item 21.
    - **Clean run repeated.** Because these changes touch a stage generator and `make_audit.sh`, the full level was run again on the final tree, and `audit/tools/CLEAN_RUN.json` comes from that run.
21. **Changes from the second release review, 2026-11-03 and 04.** At the author's request, six fresh Claude agents reviewed the release for organisation, truth and completeness, and six more wrote a full page for each of the 78 audited experiments from the published code, specs and logs. What changed:
    - **Experiment pages.** Each page now gives the instruments and data, rules, every indicator and parameter value, costs, the tuning search and how the reported variant was chosen, results with trade counts, the code and how to rerun it. Each fact names its source file. Where the earlier page was wrong, its last section says so. [experiments/README.md](experiments/README.md) is now an index of every strategy with its instruments, timeframe, indicators, search size and verdict.
    - **Numbers.** Seven quoted figures had no saved output. Their scripts were rerun unchanged, all seven reproduced, and the output is saved (audit DECISIONS 63). HCRT's true-UTC PF is 0.913, not 0.914, and one twin figure is 45%, not 50%. TA-LAB-R11 is not a test of FINAL_v4. Each correction sits beside the original in audit/CHANGES.md.
    - **Trial count.** 18 ledger rows count fewer configurations than were run. The ledger is unchanged, and the counts sit beside it in [registry/ledger_corrections.csv](registry/ledger_corrections.csv). The corrected total is 190,234.
    - **Process issues** are disclosed in audit/CHANGES.md: among them, TUNE-1-DIP's finalists do not meet its own frozen plateau rule, and TVS-1 ranked on out-of-sample Sharpe. No verdict changed.
    - **Withheld on purpose.** The gold research decision log, `goldbot/results/DECISIONS.log`, is cited by many pages but not published, because it names excluded third parties and holds account details. The live bot's own backtester is not published either, because it imports live trading modules and broker settings, so the four studies that used it cannot be rerun.
    - **iFVG.** The author decided not to publish an iFVG spec in this release, so the earlier promise to publish one before going public is withdrawn (audit DECISIONS 64).
    - **For contributors.** CONTRIBUTING.md, ADD_AN_EXPERIMENT.md, templates, issue templates and RESEARCH_AGENDA.md were added. The agenda's views come from an independent reviewer.
